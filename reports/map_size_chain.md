## Finding

The final map destination is not the fixed `2048 × 2048` `kPROJECTEDMENU` surface in the supplied map evidence. The map binds `kMENUBG`, whose allocated texture and viewport were measured at `4480 × 2428`. Whether the ISCopy source itself is the fixed `kPROJECTEDMENU` texture remains unknown until the new source-size log is captured. The observed copy was `ISCopyDynamicFetchDisabled` and reported `routedDisplayRes=false`. Before this change, the route wrapper matched only plain `ISCopy`; the dynamic-fetch-disabled render hook was installed only with frame annotations. Thus the copy used by the map could bypass the display route while map diagnostics were off. The 2.21.7 change installs the dynamic-fetch-disabled and custom-viewport hooks unconditionally for VR and applies the same map route to those variants. **SOURCE-VERIFIED** for the hook gap and correction; **LOCAL-MEASURED** for the earlier target dimensions and route=false observation.

The source now sets the map raster viewport and scissor from the latched SteamVR display extent. For `2240 × 2428` per eye, the expected SBS map destination and final composite are `4480 × 2428`. The actual ISCopy input texture size and current in-game appearance remain **RUNTIME-TO-CONFIRM**; the report does not claim the map is sharp.

## New runtime record

Once on the first map copy in each map-open interval, the log emits `[PerfMode][Map] size-chain` with map target, pixel-shader ISCopy source, ISCopy destination, route status, and `kTOTAL` composite dimensions. It is independent of the MapProbe diagnostics setting. The user should confirm that the line reports `displayRouteApplied=true`, `ISCopyDestination=4480x2428`, and `finalComposite=4480x2428`, then visually judge the map in game.
